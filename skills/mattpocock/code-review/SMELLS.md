# Smell Baseline

The Standards axis of `code-review` carries these smells, also when a repo documents nothing. The rules that bind them are in step 3 of `SKILL.md`. Each smell reads *what it is* → *how to fix*; match it against the diff.

- **Mysterious Name**: a function, variable, or type whose name doesn't reveal what it does or holds. → rename it; if no honest name comes, the design's murky.
- **Duplicated Code**: the same logic shape appears in more than one hunk or file in the change. → extract the shared shape, call it from both.
- **Feature Envy**: a method that reaches into another object's data more than its own. → move the method onto the data it envies.
- **Data Clumps**: the same few fields or params keep travelling together (a type wanting to be born). → bundle them into one type, pass that.
- **Primitive Obsession**: a primitive or string standing in for a domain concept that deserves its own type. → give the concept its own small type.
- **Repeated Switches**: the same `switch`/`if`-cascade on the same type recurs across the change. → replace with polymorphism, or one map both sites share.
- **Shotgun Surgery**: one logical change forces scattered edits across many files in the diff. → gather what changes together into one module.
- **Divergent Change**: one file or module is edited for several unrelated reasons. → split so each module changes for one reason.
- **Speculative Generality**: abstraction, parameters, or hooks added for needs the spec doesn't have. → delete it; inline back until a real need shows.
- **Message Chains**: long `a.b().c().d()` navigation the caller shouldn't depend on. → hide the walk behind one method on the first object.
- **Middle Man**: a class or function that mostly just delegates onward. → cut it, call the real target direct.
- **Refused Bequest**: a subclass or implementer that ignores or overrides most of what it inherits. → drop the inheritance, use composition.
- **Moved Complexity**: a refactor that moves complexity but leaves as much for the reader to hold. → remove a concept, or keep the old shape.
- **Bolted-on Conditional**: a conditional added to an unrelated flow. → move the logic into its own helper, state, or policy.
- **Near-Copy**: a new function that nearly repeats an existing helper. → call or extend that helper.
- **Silent Fallback**: a fallback that hides a failure that a caller or the user needs to know about. A low-level retry that no caller can act on is not this smell. → return the error, or log it and name the fallback.
- **Information Leakage**: one design decision (a format, a protocol, an ordering) is coded in more than one module, with or without an import between them. → move the knowledge into one module that the others call.
- **Temporal Decomposition**: code split by the order of execution (read, modify, write), where the steps use the same knowledge. → split by knowledge: one module owns what the steps share.
- **Overexposure**: an interface that makes callers of the common case learn about a rare option or setup step. → give the rare case a default, or its own entry point.
- **Conjoined Methods**: two functions that make sense only when read together. → join them, or move the shared knowledge so that each one reads alone.
- **Symptom Patch**: a fix that adds a case or a guard next to the cause that the bug or a comment names. → fix at the cause, or give the reason. Read the whole function around each new branch, not only the hunk. A second patch on the same rule means that the model has a wrong constraint, one that the domain does not have (Evans, ch. 8). Test: for each function where the diff adds a branch or a guard, run `git log -L :<function>:<file>`, or `git log --oneline -- <file>` when `-L` does not resolve. Two or more earlier fix commits on the same rule are a hit. → name the wrong constraint and remove it, in place of a third special case.

## Domain language (Evans, _Domain-Driven Design_)

- **Off-Glossary Name**: applies only when the brief carries a glossary. A new identifier uses a word that the glossary lists under `_Avoid_`, or a second word for a glossary concept. Or the diff changes what a glossary term means (merges two glossary concepts into one type, changes the rule of a term) and the glossary does not change in the same branch. → use the glossary term; update the glossary with the code.
- **Drifted Meaning**: the diff changes what a name means (its truth set, its units, its sentinel values), and the name stays. Callers outside the diff get the new meaning in silence, for example an `isComplete` that now also counts a checking state. → rename it, or read each caller and say why each one still holds.
- **False Cognate**: the diff reuses an existing type for a new use because the name fits, and the new path leaves a field empty, or puts another meaning in it, that existing readers depend on. → set each field that the readers rely on, with the same meaning, or give the new use its own type.
- **Scattered Rule**: one business rule is coded in more than one place (a validate, a SQL `WHERE`, a UI filter), or sits as an inline guard with a spec constant (`1.0`, `7 days`) inside a loop or a handler. The copies drift: one says `>=` and one says `>`. → one plain predicate function, named with the domain term, that every place calls. A query may do a coarse filter with no rule in it, and the predicate applies the exact rule. When the query pages or counts (`LIMIT`, `COUNT`), the exact rule runs in the query, so that a page is not short and a count is right. The loop only iterates, calls, and commits. Write a plain function, not a tree of specification classes, which APOSD calls classitis.
- **Mutable Identity**: a key (a map key, a unique index, an `ON CONFLICT` target, a dedupe set, an `===` compare) on a value that a user or another system can change, or that two things can share: a name, a URL, a path. A rename orphans the history, or two things collide. → key by a stable ID; ask what makes two of these the same thing.
- **Leaked Insides**: an exported method of a type that guards state (with a mutex, a cache, or an invariant) returns its slice, map, or pointer field without a copy, and a caller can change it. Or code outside the package builds a type that has a rule between its fields as a literal. → return a copy that reaches no guarded value: `slices.Clone` and `maps.Clone` copy only one level, so also copy each pointer or slice inside; give a type with a cross-field rule a constructor.
- **Silent Rewrite**: the code strips, replaces, or truncates a value that the user typed, so that it fits storage or another system, and does not tell the user. The stored value is not the one that the UI showed. → reject the value in the user's terms, or store it as typed and derive a safe key inside the module.
- **Dry-Run Flag**: one loop both decides and writes, or a `dryRun` or `preview` flag goes through code that decides and writes, so a later write path that misses its guard writes during a preview. → split a pure Plan that returns the decisions from a thin Apply that writes them. With no preview, Apply calls Plan itself, and Plan stays unexported, so no caller learns an order of calls (APOSD). With a preview, export Plan, and make Apply take the plan that the user saw as its argument. Apply never calls Plan again, because a second call can pick other items than the preview showed. It checks each item again at apply time, skips and reports each item that no longer qualifies, and never adds one.
- **Incidental Reliance**: a new caller depends on behavior that the callee does not promise in its name, type, doc comment, or tests: the order of a query with no `ORDER BY`, insert order, map order, the first element as the newest. → add the promise (an `ORDER BY`, a doc line, a test), or do not depend on it.
